# IPC アクセスと移行

[English](IPC-SECURITY.md) | [简体中文](IPC-SECURITY.zh-CN.md) | [繁體中文](IPC-SECURITY.zh-TW.md) | **日本語**

[ドキュメント](README.ja.md)

英語の User 設定は **Live Share Workspace Bridge: Configure IPC Access** で構成します。信頼を決めるのは明示的な User 値だけで、ワークスペース設定や拡張が提供する既定値で範囲を広げることはできません。

| モード | ブリッジ所有者以外へのアクセス |
|---|---|
| ownerOnly | なし。公開版の既定。 |
| selectedUsers | 保存済みの ipc.selectedUserSids と一致する現在のローカルユーザー。 |

所有者はドメインユーザーであっても保持し、追加の許可はローカルユーザーだけです。リモート接続は拒否し、すべてのクライアントはブリッジと同じ Windows session ID である必要があります。ドメインコントローラーでの追加アカウント列挙は拒否します。

信頼は許可されたアカウントのすべてのプロセスに及び、一つの agent タスクに限定されません。ブリッジの呼び出しはどの agent のファイルシステムサンドボックスの境界外でもありますが、agent／操作権限には引き続き従います。Host アクセスは独立しており、有効でほかの条件も満たせば Host コマンドを許可し得ます。選択画面は範囲を広げる前に警告します。エラーの自動回避策として広いモードを有効にしてはいけません。

選択画面は現在の名前を表示しますが、保存するのは SID です。改名してもアクセスは維持され、削除後に同名で再作成したアカウントは名前による選択を引き継ぎません。利用できない／不正／非ローカルの SID は報告され、許可されません。キャンセルすると設定は変わりません。

## 互換移行

ipc.accessMode に明示的な User 値がなく、旧 ipc.allowCodexSandboxClients が true の場合、初回移行は既存の CodexSandboxOffline/Online の身元だけを解決し、その SID をキャッシュして、ipc.selectedUserSids と selectedUsers を保存します。キャッシュした SID は名前で再解決せず、存在しないアカウントにはアクセスを追加しません。最初のスナップショットより前に削除／再作成された過去の SID は、ブール値からは復元できません。不明な場合は身元を確認してください。

明示的なモードは旧フラグより優先します。false／未設定は ownerOnly のままです。曖昧な手編集の選択や観測された同時変更は上書きしません。旧フラグは互換のため残りますが、モードが明示された後は新しいバージョンでは無視されます。実行中の旧版ウィンドウでモードを有効にするには、更新／再読み込みが必要です。

操作権限スイッチは後続のリクエストに即時反映されます。IPC 信頼の変更と移行は User 設定を書き込んでブリッジを再起動し、instance/epoch が変わります。必要な配備承認を得て、依存作業を一時停止し、再検出してください。この手順で Host 権限、アカウント、資格情報、ACL ポリシー、実行ポリシーを変更することはなく、送信済みの効果も元に戻しません。

## 削除された allLocalUsers モード

バージョン 0.3.0 で allLocalUsers は削除されました。agent は MCP サーバーを通じてブリッジに到達し、そのサーバーは agent があなた自身の Windows アカウントで起動するため、その経路は ownerOnly で対応できます。他のアカウントには selectedUsers を使ってください。

User 設定に allLocalUsers が残っていても、ブリッジは失敗しません。ownerOnly として動作し、起動のたびに出力チャネルへ一行を書き込み、ウィンドウセッションごとに一度だけ Configure IPC Access ボタン付きの通知を表示します。設定は書き換えないため、通知を止めるには自分で値を変更してください。info と lswb_status は ipc.mode を ownerOnly とし、ipc.requestedMode に allLocalUsers、ipc.deprecatedModeIgnored に true を報告します。それ以外の不明な値では、引き続きセットアップエラーでブリッジが停止します。ネイティブヘルパーは allLocalUsers を拒否します。

## 設計上の境界

ネイティブパイプは明示的な SID 許可、リモート拒否、同一セッションの確認、持続する単一のサーバーインスタンス、上限付きの入力／応答処理を使います。ローカル SAM の列挙はドメインコントローラーでは拒否します。これらは現在の制約であり、すべての Windows ポリシー、リモートホスト、アカウント種別で検証済みであることを保証するものではありません。アクセス／エラーの切り分けは[起動診断](STARTUP-DIAGNOSTICS.ja.md)を参照してください。
