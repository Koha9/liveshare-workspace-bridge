## インスタンスまたは共有ルートが見つからない

Live Share Guest ウィンドウの Profile に拡張機能をインストールします。更新後にウィンドウを再読み込みし、対象セッションに接続して CLI の `instances` を実行します。ローカルウィンドウのインスタンスは `roots` が空の場合があります。プロジェクト名と完全な `vsls:` URI で Guest を選びます。停止した接続は **Live Share Workspace Bridge: Restart Connection** で再開できます。同名の出力チャンネルにパイプ起動エラーが記録されます。

以前のローカルパッケージから移行する場合は `ucuni-local.liveshare-workspace-tools` または `Koha9-Lee.liveshare-workspace-tools` をアンインストールし、`Koha9-Lee.liveshare-workspace-bridge` をインストールして対象ウィンドウを再読み込みします。名前の変更後は別の拡張機能として扱われるため、新旧を同時に実行しないでください。PowerShell のパスを設定していた場合は `liveshareWorkspaceBridge.powershell` に移してください。

## バインド、編集、保存

再読み込みでインスタンス ID が変わり、ワークスペース変更で epoch が更新されます。バインドエラーの後は対象プロジェクトを再選択します。`content_changed` の場合は対象部分だけを読み直し、現在のバージョンで編集を修正します。未保存ドキュメントは既定で保護されます。既存の未保存変更も含める意図がある場合にのみ編集を許可します。

編集が適用されても保存は失敗する場合があります。ファイルごとの保存結果と dirty 状態を確認し、必要なら返されたバージョンで `save` のみを再試行します。通信失敗で `requestSent:true` の場合、結果は不明です。対象の状態を確認するまで変更を再送しないでください。

## 検索と言語機能

内容検索は `complete:null` の検索ビューのスナップショットを返し、完了通知はありません。ファイル名検索は新規ファイルを見落とす場合があります。空の結果は不存在の証明になりません。既知のパスは直接読み取れます。言語機能はプロジェクトのプロバイダーに依存し、空の診断はビルドやテストの成功を意味しません。

## テキスト、バイト列、サイズ制限

ドキュメント編集は Guest バッファーの改行形式を保持します。Host への保存時に Live Share が改行を変換する場合があります。Guest テキストや `providerRead` は Host の元バイト列、文字コード、改行の完全一致を証明しません。この版は汎用バイナリ書き込み、ディレクトリコピー、再帰削除、Host shell を提供しません。

`response_limit` の場合は要求する行数やファイル数を減らします。部分的な応答はプロバイダーのストリーム読み取りを意味しません。[API の制限](API.ja.md)と[使い方](USAGE.ja.md)を参照してください。
