## 接続と権限

Live Share Guest ウィンドウの Profile に拡張を入れます。更新後はウィンドウを再読み込みし、対象セッションへ再接続して CLI `instances` を実行します。ルート名と完全な `vsls:` URI で選び、instance/epoch/workspace を保持します。再読み込み後のバインド不一致は再検出が必要です。拡張 Output にパイプ起動エラーが出ます。

**Live Share Workspace Bridge: Configure Agent Permissions** を開き、構成値と実効権限を確認します。agent は既定有効、共有端末は無効です。ユーザー管理の設定を agent が自分で有効にして拒否を迂回してはいけません。変更は新規作業を止め、送信済み効果を戻しません。

## Host 端末がない／応答しない

接続済みの共有 RW Windows PowerShell が必要です。通常 Guest 端末は選びません。不在時は skill が一度だけ共有を依頼して待ちます。複数候補は正確な名前を指定し、推測や順番の試行、別経路への切り替えはしません。ユーザー確認後に一度検証し、失敗なら報告して待ち、再質問やポーリングを繰り返しません。

バインドは所有するランダム bootstrap でルートを照合します。送信済みリクエストがタイムアウトしたらチャネルを隔離し、変更を再送しません。記録と対象状態を確認し、ユーザーが端末の待機／再起動を確認してから `acknowledgeRecovery:true` で明示再バインドします。診断はカウンターのみで、取得したファイル内容を含めません。

実際の大容量ダウンロードで端末が停止したため、本版では無効です。バイト読み取りの反復で模倣しません。大容量アップロードと上限付きバイト API には実測証拠があります。出力ペーシングは持続的ダウンロードの修復として未検証です。必要ならユーザーへアクセス可能なコピーとローカルパスを依頼します。

## 編集と Host 変更

現在の文書バージョンで編集を保護し、既存の未保存内容を保持します。適用済みで保存に失敗した場合は、受領したバージョンで `save` のみ再試行し、編集全体を再適用しません。保存はファイル単位であり、トランザクションではありません。

Host 書き込み後に Guest バッファーが古い／dirty のままの場合があります。`editor_refresh_pending/external_change_dirty_document` で保護し、全エディター revert は行いません。ユーザーに競合解決や安全な再オープンを依頼します。`hostStat` の `withTextHash:true` は期待ダイジェストのみを更新し、エディターは更新しません。既知の古い内容を保存しません。Guest テキスト／EOL と生バイトは別で、Host Git がパッチ出力を CRLF にする場合があります。

## 検索と言語ツール

Host rg は保存済みファイルを検索します。上限／失敗で complete は false、無一致の終了コード 1 は正常です。dirty 文書は別に報告し、自動保存しません。スナップショットは不完全です。言語ツールにはプロバイダーが必要で、不在なら有効化や手動処理を依頼します。診断ゼロはビルド／テスト合格を意味しません。

## ファイルとその他の制約

バイト上書きには現在の Host 生 SHA-256 が必要です。ディレクトリコピーは新規宛先のみで、失敗時に部分結果が残る場合があります。再帰削除はユーザーへ実行と確認を依頼します。複数ファイルの原子的保存は適切な Host ツール、またはファイル単位保存への明示的同意が必要です。未解決の手順ごとに一度、正確なパスと結果を示して依頼し、依存作業は返答まで待ちます。黙って省略したり raw コマンドで迂回したりしません。

`response_limit` では必要範囲／少ない結果を要求します。部分テキスト応答は基底プロバイダーのストリーミングを意味しません。[API](API.ja.md)と[検証記録](VALIDATION-v0.2.ja.md)を参照してください。
